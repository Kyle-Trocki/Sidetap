# Sidetap acceptance audit

Reviewed October 4, 2026. Actions run on a gesture of two or more taps. Calibration collects eight double taps and eight triple taps, and Sidetap learns the sound of a tap and the pace between taps from them. Sidetap saves one calibration and one set of gestures and actions. It has no zones, no per-desk profiles, and no location access.

The measurements in this audit that came from real taps were taken with the earlier four-zone calibration. Each one says so. Nothing is measured on real taps with the current calibration.

## Evidence status

| Requirement | Current evidence | Status |
| --- | --- | --- |
| Native macOS MVP | `Sidetap` builds in Debug and Release as a sandboxed, single-window SwiftUI macOS application targeting macOS 14+. Closing its only window terminates capture with the app. | Automated build verified |
| Built-in MacBook audio only | Capture is pinned to the built-in microphone, and the Active/Hybrid probe to the built-in speakers, by Core Audio transport type, whatever the system default is. With no built-in microphone, capture is refused. The non-GUI route check reports this Mac's microphone and speakers as built-in while AirPods are the system default, and five policy tests cover valid and invalid routes. | Automated policy and current route verified |
| Tap calibration | Calibration asks for eight double taps and then eight triple taps after explicit setup consent. An attempt counts only when it has exactly the gesture's taps and every tap passes the weak, noisy, and clipped checks; otherwise the app says what to change. Listening stops between the two gestures and after a pause. Undo removes the last gesture. Talking is the recommended negative, and other negatives are optional. Unit tests cover the gesture order, the attempt rules, and the retry guidance. | Protocol automated; physical workflow pending |
| Tap gestures | A double tap and a triple tap each run their own action, and you can add gestures of four or more taps without limit. Every gesture uses the same tap model and the same gap between taps, so an added gesture needs no calibration. The gap is 1.3 times the slowest calibrated pause, never under 0.45 s and never over 0.8 s. The gesture with the most taps runs at its last tap, and any other runs once no further tap arrives. Unit tests cover the tap counter, the learned gap, and gesture actions, including added gestures. With the earlier four-zone calibration, recorded gestures from one setup ran their action for 19 of 20 double taps and 20 of 21 triple taps. | Automated logic verified; unmeasured with this calibration |
| Native anti-slop interface | Standard macOS navigation, lists, forms, tables, toolbars, and controls are used. The calibration screen shows one gesture at a time with a row of dots for the taps heard; the Desk screen shows the current gesture and each gesture's action. Liquid Glass is limited to functional primary controls on macOS 26. | Source and build verified; visual review pending |
| Diagnostic recorder | Diagnostics reports selected input/output routes and built-in status, exposed channels, sample rate, buffer timing/jitter, frequency response, signal quality, and labeled feature captures. | Implemented; live capture output pending |
| Sensing approaches | Passive, active-probe, and hybrid feature schemas are implemented and selectable at calibration, and an injected-chirp regression verifies active correlation and delay recovery. The app has no comparison of the approaches: the earlier one scored zone accuracy and was removed with zones. | Automated logic verified; approaches not compared |
| Saved calibration | One feature-only versioned JSON file stores the trained tap model, the learned gap between taps, and each gesture's action. A file from an earlier version is skipped by version before decoding, and the per-desk four-zone profiles are no longer read, so the app asks for a new calibration. A current file is checked for a consistent model and a valid gap. Malformed files, initialization failures, and write failures are surfaced instead of reporting false success. | Persistence automated |
| Real-time recognition path | Streaming onset detection, a 90 ms capture that starts 12 ms before the onset, a full-event sustained-sound gate, one shared spectrum analysis, and the tap model are connected. A sound counts as a tap when it passes the quality checks, is close enough to a calibrated tap, and is no closer to a recorded negative. The closeness threshold comes from how much taps vary from one calibrated gesture to the next. A tap counter groups taps into gestures. Capture generations discard observations queued before a stop or strategy change. A synthetic chunked pipeline test trains on detected taps, accepts a held-out tap, and rejects an impact with a different resonance. Detector tests cover a tap late in a 100 ms buffer and a tap right after a rejected sound. | Synthetic integration and build verified; live use pending |
| Configurable local actions | Visual-only, system sound, copy text, paste text, speech, HTTP(S), user-named Shortcut, user-selected application or item, shell command, recorded keyboard shortcut, media key, and full or selected-area screenshot actions are implemented. Screenshots go to the Desktop, the clipboard, or both. Every gesture is visual-only by default. Automatic side effects run only on Desk, not while editing or calibrating. A shared validated planner drives both inline Test and live gestures. Shell commands are clearly labeled as automatic and run with Sidetap's sandbox permissions. | Planning, build, and persistence verified; paste, screenshot, keyboard shortcut, and media key actions not yet confirmed in the running app |
| False-trigger rejection | Weak, noisy, clipped, out-of-distribution, schema-mismatched, and calibrated-negative observations are rejected. Onset learns the room for 0.75 seconds and requires a brief impact; complete candidates with sustained speech-like duration and energy are dropped before classification. Deterministic regressions reject a plosive-plus-voiced speech candidate and elevated background while preserving short and resonant taps. Talking can also be captured as a negative during calibration. The active probe is filtered out of onset detection. In live use, taps within 300 ms of a physical key press or click are ignored, and no actions run above a room noise limit. With the earlier four-zone calibration on one setup, the typing check removed all 38 detections in 45 seconds of typing, and 2 minutes of loud-room audio produced no gestures. | Automated verified; unmeasured with this calibration |
| Local processing and privacy | Signal processing is local. Raw audio is discarded unless debug capture is explicitly enabled; retained WAVs remain visible and deletable after relaunch. | Source and persistence verified; runtime privacy observation pending |
| Immediate pause and recalibration | Toolbar pause stops input/probe and disarms guided capture. Pause remains sticky. Recalibration preserves the gestures and their actions. | Build verified; runtime interaction pending |
| Response latency | Response latency is mapped from each audio buffer's monotonic `AVAudioTime` host timestamp through feature extraction and main-thread delivery, with sample-offset and elapsed-time regression coverage, and diagnostic captures record it. The app has no test that reports a median: the earlier zone accuracy test measured 175 ms on one setup. This is a single tap's path; a gesture other than the one with the most taps runs about 0.7 s after its last tap by design. | Instrumentation automated; unmeasured with this calibration |
| Continuous 30-minute stability | The synthetic soak in `--fast` mode completed 900,000 events: 810,000 of 810,000 taps accepted and 90,000 of 90,000 rejection challenges rejected, with RSS 6.9 → 7.1 MB. It doesn't exercise AVAudioEngine, permissions, UI, or actions. | Synthetic evidence; live soak pending |
| Automated core tests | 57 unhosted tests pass with zero failures. | Verified |
| Documentation | README covers actions, installation, setup, gestures, and privacy. CONTRIBUTING.md covers build, test, and verification tools. | Verified |

## Remaining completion gates

The MVP must not be called physically validated until all of the following are captured on the target MacBook and desk:

1. A calibration with real double and triple taps in the final laptop position.
2. Double taps, triple taps, and at least one added gesture confirmed to run their actions in live use, including the Paste text, screenshot, keyboard shortcut, and media key actions.
3. A count of missed gestures and accidental gestures over a representative session. The app has no built-in test for this.
4. A 30-minute live microphone/action run including taps, conversation, typing, laptop touches, and representative background noise.
5. A visual interaction review of every screen at normal and minimum window sizes.

All five gates are open.
